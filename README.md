# geo-workflow

> 把「知识库 → 生文 → 校对 → 文档导入 → 多平台发布 → 结果回填」这条人工内容生产链路，做成一套可复用、可在无人值守下跑完的自动化系统。

已在 **6 个客户项目**（教育、快消、汽车行业）真实落地，累计交付 **250 篇**内容、完成 **900+ 次**跨平台发布，单轮最大批量 **36 篇**。

---

## 一、它解决什么问题

GEO 内容交付原本是一条纯人工流水线：

```
知识库下载 → 生文提示词 → 文章生成 → 审查校对 → 文档导入 → 多平台发布 → 交付回填
```

痛点有三个：

1. **重复度高**：同一套流程在每个项目、每个批次里重来一遍；
2. **容易出错**：人工复制粘贴、标题错位、图片漏传、发错平台；
3. **耗时随篇数线性增长**：8 篇约 4 小时（生文 2 小时 + 发布 2 小时），36 篇就是一个工作日以上。

自动化后，**单批 8–36 篇的耗时都收敛到 2 小时左右**（生文、发布各约 1 小时），因为流程内部可并行。

## 三、真正的难点：环境不可控

流程编排本身不难。难的是**发布目标是 9 个第三方平台，它们随时会变**：登录态会过期、页面改版会让选择器失效、发帖有频率限制、风控会让结果变得不确定。

系统必须让一个**必然会失败的动作，在无人值守下收敛成确定的结果**。为此实现了五个机制：

| 机制 | 解决什么 | 实现要点 |
| --- | --- | --- |
| **平台节流保护** | 触发平台频控导致发布失败 | 单平台发帖间隔检测，距上次发布不足 5 分钟自动等待（日志：`距上次发布不足5分钟，等待 231 秒`） |
| **状态持久化 + 断点续跑** | 批量跑到一半中断，只能从头再来 | 以「文章 × 平台」为最小状态单元落盘；中断后按序号续发，已完成的不重复处理 |
| **失败重试与幂等** | 偶发失败重试后重复发布 | 失败分类（可重试 / 不可重试）；重试前先查询目标平台状态，保证幂等 |
| **风控降级** | 平台风控导致"结果不明" | 未捕获明确成功标志时按已提交处理，交由后续状态抓取确认（日志：`未检测到明确成功标志，按已提交处理（稍后在"我的发帖"确认）`） |
| **结果对账** | 以为发出去了，其实没发 | 发布后抓取状态 → 链接回填 → TSV 汇总 → 抽样校验，异常可重跑且不污染已完成结果 |

五个机制的完整说明（含问题场景、代码位置、日志证据）见 [`docs/reliability.md`](docs/reliability.md)。

## 四、可度量的工程

系统自带成本与质量度量，不靠感觉判断优化是否有效：

| 指标 | 基线（单轮 36 篇） | 优化目标 |
| --- | --- | --- |
| 子代理合计成本 | ¥6.94 | ≤ ¥2.5 |
| 单篇文章成本 | ¥0.42 | ≤ ¥0.15 |
| 每代理平均调用次数（3 篇） | 42 | ≤ 12 |
| **校验通过率** | **36/36** | **不得下降** |

> **只看成本下降、不看校验通过率的优化是失败的优化。**

度量方法与归因脚本见 [`skills/geo-article-workflow/references/成本模型与度量.md`](skills/geo-article-workflow/references/成本模型与度量.md)。

## 五、新增一个平台要做什么

这是这套系统可扩展性的体现 —— **主流程零改动**：

1. 在 `skills/article-publisher/platforms/` 下新增一份平台 playbook；
2. 在 `scripts/<平台>/` 下实现发布脚本（登录、正文清洗、发布、状态查询）；
3. 在批次配置里登记平台名与新平台的发布约束（间隔、图片策略、标题规则）。

其余 8 个平台不受影响，一个平台改版也不会波及其他平台。

## 七、快速开始

**生文侧**

```bash
cd skills/geo-article-workflow

# 1. 初始化项目目录
python3 scripts/create_project.py <项目名>

# 2. 从 IMA 知识库下载素材
python3 scripts/ima_download.py <知识库关键词>

# 3. 批量生成生文提示词
python3 scripts/generate_prompt.py <项目问题集目录>

# 4. 导入到飞书 / 腾讯文档（先复制 templates 下的配置模板并填好）
python3 scripts/feishu_import.py <配置路径>
python3 scripts/tencent_import.py <配置路径>
```

**发布侧**

```bash
cd skills/article-publisher
npm install          # 安装 playwright 依赖
node scripts/common/login.js <平台>       # 首次登录并保存登录态
node scripts/<平台>/publish_<平台>.js     # 单篇或批量发布
```

## 八、安全与脱敏说明

本仓库是**脱敏后的公开版本**：

- 仓库内**不包含**任何平台登录态（cookie）、API 密钥、token；
- 客户名称与项目名已替换为「示例项目 X」；
- 飞书/腾讯文档配置模板中的 `app_id` / `app_secret` / 域名 / 目录名均为占位符，使用前需自行填写；
- `.gitignore` 已排除 `node_modules/`、`__pycache__/`、`feishu_tokens.json`、登录态文件、发布日志与批次产物。

> ⚠️ 如果你要基于本仓库二次使用：**不要把 `平台登录状态-*.json`、`feishu_tokens.json`、`.env` 提交到任何公开仓库。**
