# GEO 文章生文自动化工作流（geo-article-workflow）

把“生文项目”的标准流程固化为可复用工作流：**初始化 → 生成 prompt → 生成文章 → 审查校对 → 导入在线文档**。

两条基本原则：

1. **能脚本化的就脚本化**：所有确定性操作都在 `scripts/` 下，优先调用脚本，不要每次手写一次性命令。
2. **详细执行细节按需读取**：本文件只放流程骨架与红线；每一步的具体做法、脚本参数、坑位在 `references/` 下按需加载（见文末索引）。

## 适用场景

- 用户给出一个“生文项目”（如示例项目A、示例项目B），要求按步骤生成文章。
- 用户提到需要下载 IMA 知识库、创建项目目录、生成生文prompt、生成文章、审查校对、飞书导入或腾讯文档导入。
- 用户要求“每完成一个步骤先让我确认再继续下一步”。

## 工作区与依赖

- 项目目录：用户指定的项目根，或 `cwd/<项目名>/`。所有相对路径以项目根为准。
- 依赖：Python 3、`openpyxl`、`python-docx`；腾讯文档导入另需 `requests`。

| 脚本 | 用途 |
|:--|:--|
| `scripts/create_project.py` | 创建项目目录结构 |
| `scripts/ima_download.py` | 从 IMA 下载知识库 |
| `scripts/build_writer_kit.py` | **为子代理生成单文件任务书**（事实卡 + prompt + 契约） |
| `scripts/generate_prompt.py` | 按参考 prompt 与变量组合生成生文prompt |
| `scripts/check_articles.py` | 文章自动化校对检查 |
| `scripts/check_budget.py` | **下发子代理前检查余额与本批预估消耗** |
| `scripts/make_whitelist.py` | 生成导入白名单 |
| `scripts/check_feishu_token.py` | 导入前检查飞书 token 是否有效 |
| `scripts/feishu_import.py` | 飞书批量导入（含图片上传） |
| `scripts/tencent_import.py` | 腾讯文档批量导入（md→docx→原生在线文档） |

模板：`templates/feishu_config_template.json`、`templates/tencent_config_template.json`。

## 流程骨架

### 步骤 0（前置）：项目初始化

判断 `cwd/<项目名>/` 是否存在；不存在则用 `create_project.py` 建骨架，按需用 `ima_download.py` 拉知识库，
然后向用户收齐输入（问题目录、参考prompt、公共prompt、校对提示词、知识库、导入凭证）。
**开始步骤一之前必须让用户确认初始化完成。**

→ 细节读 `references/步骤0-项目初始化.md`（含目录结构规范）。

### 步骤 1：生文提示词生成

每个问题产出 `生文提示词/生文prompt<序号>.md`，并更新 `变量组合对照表.md`。
编号接续已有最大编号，**不跳号、不覆盖**；变量组合由主会话定死（与已有组合不完全重复；
变量池用尽时才按顺序复用并照常记录）。

→ 细节读 `references/步骤1-生文提示词.md`。

### 步骤 2：文章生成

产出完整 `.md` 文章到各问题 `文章/` 目录，**文件名 = 主标题**。
这是全流程的成本大头：主会话先写一份**事实卡**，用 `build_writer_kit.py` 拼成**一份任务书**，
子代理只读这一个文件、只写文章、只回一行简报。

→ 细节读 `references/步骤2-文章生成.md`，机制与成本依据见 `references/子代理运行策略.md`。

### 步骤 3：文章审查校对

先用自定义/通用校验脚本**一次性跑全量**，再人工核对约稿特殊要求、易错口径、数据准确性、格式规范。
小修由主会话直接 `edit`；超字数让子代理回 cut list；只有整篇重写才复用原代理。
修改点整理成表格，用户确认后进入步骤四。

→ 细节读 `references/步骤3-审查校对.md`。

### 步骤 4：文档导入（飞书 / 腾讯文档，按需选择）

按用户指定平台导入为可编辑在线文档，图片随文档上传。只导入本轮新增（白名单必须带 `.md` 扩展名），
导入前先校验 token，完成后输出「优化问题 → 文档链接」汇总表。

→ 细节读 `references/步骤4-文档导入.md`。

## 子代理（唯一红线）

> 详细策略、契约模板、反模式与验收指标见 `references/子代理运行策略.md`（准备下发子代理时读）。

**下发子代理之前必须**：运行 `scripts/check_budget.py --articles N`（或 `--prompts N`），
把**账户余额、本批预估消耗、风险等级**原样告知用户，并说明余额不足的后果
（中途 429/402，已落盘产物保留但收尾会丢），**等用户确认后再开跑**。

三条落地要求（它们决定成本，也决定稳定性）：

- **任务书单文件**：子代理只读 `build_writer_kit.py` 生成的那一个文件，不要 ls/grep/读其他文件。
- **零解释契约**：禁止输出计划、复述、解释、总结；除工具调用外每次回复不超过一行；一次性写完文件。
- **校验不在子代理里做**：由主会话一次性跑全量。

## 通用要求

- 每完成一个步骤先让用户确认，再进入下一步。
- 不明确的地方必须向用户提问，不要猜测。
- 用户指定数量/变量组合时严格按指定数量生成；历史文件默认保留。
- 重材料（docx/xlsx）先在主会话转成纯文本或事实卡，避免 N 个子代理重复解析。
