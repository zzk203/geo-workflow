# 步骤 3：文章审查校对

> **何时读**：本轮文章已写完，要做自动校验 + 人工核对时。

---

## 输入 / 输出

- **输入**：`<项目名>文章校对提示词.md`、`需求和参考/<约稿需求>.docx`、`知识库/`、本次新增文章。
- **输出**：**直接修改文章文件**；并把修改点整理成表格写入 `问题集/校对修改汇总_新N篇.md`。

## 一、先跑确定性校验（主会话一次性跑全量）

```bash
python scripts/check_articles.py "问题1/文章" "问题2/文章" ... \
  --competitors "蔚来ES8,问界M9,问界M8,沃尔沃EX90,蔚来ES9"
```

项目若已有更贴合的自定义校验脚本（如按问题校验价格口径、版本边界的版本），优先用它，因为它比通用脚本更准。

校验通常覆盖：禁用词、备选标题数量与字数、主标题字数与是否在正文重复、图片数量与路径真实性、有效字数区间、价格口径、其他车型是否被加粗、Q&A 格式。

## 二、再人工核对

- 约稿需求中的特殊要求（如「XX怎么样」需包含客观短板）。
- 易错表述（示例，按项目实际调整）：座椅调节表述、竞品空悬品牌、屏幕尺寸、壳体占比、后排屏幕意义、制动盘类型、车身结构表述、激光雷达位置、后轮转向「同级最小」、侧碰防护倍数、Type-C/无线充电数量、空气弹簧叫法等。
- 数据准确性：价格、续航、功率、尺寸、悬架品牌、制动卡钳、轮胎规格。
- 图片 1-2 张、禁用词、加粗规则、标题/备选标题、Q&A 格式。

## 三、修怎么改（省钱的顺序）

按代价从低到高：

1. **主会话直接 `edit`** —— 改字、补句、改表述、删冗余句，一律用编辑工具做定向替换。
2. **让子代理只回「cut list」** —— 若整篇超字数，不要让它重写整篇：让它输出「行号 + 删除原因」，主会话按清单 `edit`。
3. **`send_message` 复用原文章代理** —— 只有「整篇结构性问题需要重写」才用，且优先复用而不是新开代理（新代理要重新建立上下文）。
4. **绝不为了小修新开一个子代理并重写全文** —— 实测这是纯浪费。

## 四、完成标准

修改完成后把修改点整理成表格，向用户确认后再进入步骤四。
