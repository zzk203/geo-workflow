# 步骤 1：生文提示词生成

> **何时读**：要为本轮新增文章生成 `生文提示词/生文prompt<N>.md` 时。
> 涉及下发子代理的部分，按需再读 `references/子代理运行策略.md`。

---

## 输入 / 输出

- **输入**：每个问题的 `生文prompt参考.md`、`变量组合对照表.md`、用户确认的篇数与变量组合要求。
- **输出**：各问题 `生文提示词/生文prompt<序号>.md`，并更新 `变量组合对照表.md`。

## 一、编号与保留策略

- 新 prompt 编号**接续该问题已有最大编号**，不跳号、不覆盖旧文件。
  例：该问题已有 prompt1–7，则本轮从 `prompt8.md` 开始。
- 增量轮次默认保留全部历史文件。

## 二、变量组合决策（主会话做，子代理不做）

- 先从 `变量组合对照表.md` 读出**已用组合**与**可用变量池**。
- 新组合要与已有组合**不完全相同**（至少一个维度不同）；同批内彼此也不相同。
- 只有当变量池的取值全部用过、无法再拼出新组合时，才按「从头按顺序复用之前的组合」处理，**并照常记录**。
- 同一问题内尽量错开：文章类型 / 轮换组 / 主展开角度 / 小标题标签 / 引言场景 / 清单结构 / 优势标签 / 场景收束。
- 把定死的变量写成**本轮规范文件**（如 `.geo-work/<项目>_round<N>_spec.md`），逐篇列出该用哪一行变量。

## 三、生成方式

可用 `scripts/generate_prompt.py`：

```bash
python scripts/generate_prompt.py \
  --reference "问题N/生文prompt参考.md" \
  --output "问题N/生文提示词/生文prompt3.md" \
  --author "C. 高净值真实车主" \
  --type "场景化对比型" \
  --main "全尺寸气场、行政礼宾出行" \
  --sub "百万级底盘、不败金身安全" \
  --competitors "蔚来ES8、问界M9" \
  --comment "<!-- 变量组合：... -->" \
  --table "问题N/变量组合对照表.md" \
  --row "| 3 | 场景化对比型 | ... |"
```

- 若参考 prompt 中不同文章类型的正文结构差异较大，把对应类型的 `### 3. 正文结构` 段落存成文本文件，用 `--structure-block` 传入，让结果只保留选定结构。
- prompt 中的生文格式严格参考 `生文prompt参考.md`，两处例外：
  - 删除禁用 md 格式相关的提示词；
  - 写 `1.` 这类序号时不要用 md 的 ol 形式（序号后直接接内容，不加空格）。
- `变量配置表` 统一用 `| 变量名 | 选定值 |` 表头。

## 四、下发子代理

- 子代理只写 prompt 文件，**不跑校验**。
- 任务书用 `scripts/build_writer_kit.py --kind prompt` 生成，子代理**只读任务书这一个文件**。
- 变量配置、价格口径、框架编号由主会话在规范文件里定死；子代理只执行、不决策。
- 完整机制（零解释契约、素材包、余额闸门）见 `references/子代理运行策略.md`。

## 五、完成标准

- 每完成一个问题的 prompt 生成，向用户展示该问题的变量组合对照表并确认。
- 全部完成后，向用户汇报「问题 → 新增 prompt 编号 → 篇数」，确认后再进入步骤二。
