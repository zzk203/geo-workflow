# 可靠性设计：五个机制

> 这套系统的核心不是"能不能发"，而是"**发失败了怎么办**"。
> 发布目标是第三方平台，环境不可控 —— 登录态会过期、页面会改版、平台会限流、风控会让结果变得不确定。
> 下面五个机制，就是让一个必然失败的动作，在无人值守下收敛成确定结果。

---

## 1. 平台节流保护

**问题场景**：连续发帖会触发平台的频率限制，轻则发布失败，重则账号被限流。

**方案**：发布前检查该平台距上次发布的间隔，不足阈值则主动等待，而不是硬冲。

**证据**（发布日志）：

```
[淘江湖] 距上次发布不足5分钟，等待 231 秒
```
```
[知乎] 间隔保护，等待 43 秒后继续
```

**设计取舍**：等待会拉长批次耗时，但比"发失败再重试"更划算 —— 失败重试可能已经触发了风控，代价更高。因此**宁愿慢，不要错**。

---

## 2. 状态持久化 + 断点续跑

**问题场景**：一批 36 篇 × 5 个平台 = 180 个发布动作，中途断网、机器休眠、人工中断都是常态。如果没有状态记录，只能从头再来 —— 而已发布的文章不能重发。

**方案**：

- 以「**文章 × 平台**」为最小状态单元，每完成一个单元立即落盘；
- 状态文件记录进度（批次日期、已完成数量、最后处理位置）；
- 提供一个"续跑"入口，启动时先读状态，跳过已完成单元，只补未完成的。

**证据**：

```
resume_taohu_234.sh        # 从第 2 篇续跑到第 4 篇
resume_non_taohu.sh        # 续跑非淘江湖平台
taohu_publish_state.json   # { "date": "2026-09-08", "count": 4, "last": 1788864675241 }
```

**核心约束**：续跑**不得污染已完成结果** —— 已完成单元不再重复提交、不再重复校验。

---

## 3. 失败重试与幂等

**问题场景**：网络抖动导致的失败，重跑一下就过了；但盲目重跑可能把已经发出去的文章再发一遍。

**方案**：

- **失败分类**：
  - 可重试：网络超时、页面加载失败、登录态瞬时失效 → 自动重试；
  - 不可重试：内容校验不过、平台明确拒稿 → 标记人工处理，不浪费轮次。
- **幂等保证**：重试前先调用 `query_status`，确认该文章在该平台是否已存在（草稿或已发布），已存在则跳过。
- **单篇重试入口**：失败项可单独重跑，不影响批次其他部分。

**证据**：

```
taohu_headed_article3_retry.log    # 单篇重试
taohu_headed_article4_retry.log
```

---

## 4. 风控降级：结果不确定时怎么办

**问题场景**：最麻烦的不是"失败"，而是"**不知道成没成功**"。平台风控介入时，页面既不给成功标志，也不给明确报错。

**方案**：把结果从二元（成功/失败）扩展为三元（成功 / 失败 / **不确定**）：

- 未捕获到明确成功标志时，**按已提交处理**，避免重复发布；
- 同时把该条目标记为"待确认"，交由后续的状态抓取环节核实；
- 抓取结果回填后，人工只需处理真正异常的少数条目。

**证据**（发布日志原文）：

```
[淘江湖] 未检测到明确成功标志，按已提交处理（稍后在"我的发帖"确认）
```
```
注意：如页面显示 403 风控，请到创作中心确认文章是否已变为"已发布"；未发布则需人工再点一次发布。
```

**设计取舍**：宁可漏报（少发一篇，人工补），不可误报（重复发布，影响账号）。这是**风险偏好上的主动选择**，不是实现缺陷。

---

## 5. 结果对账

**问题场景**："我以为发出去了"是这类系统最危险的错觉。

**方案**：发布之后还有一道独立闭环 ——

```
抓取发布后状态（collect / dump）
      ↓
链接回填（backfill）
      ↓
TSV 汇总（发布汇总.tsv：文档链接 / 平台 / 标题 / 发布链接）
      ↓
抽样校验（spot_check）
```

- 每条记录都能追溯到"哪篇文章、发到哪个平台、结果链接是什么"；
- 汇总表就是交付物，也是人工核对的唯一入口；
- 异常条目在表里明确标出，可直接重跑对应单元。

**证据**：每个批次目录下的 `发布汇总.tsv`、`logs/<平台>_result.tsv`、`links.json`。

---

## 附：这五个机制解决的是同一类问题

| 机制 | 一句话本质 |
| --- | --- |
| 节流保护 | 尊重外部约束，不做无效重试 |
| 状态持久化 + 断点续跑 | 把长任务切成可恢复的小单元 |
| 失败重试与幂等 | 区分"能重试"和"不能重试"，重试必须幂等 |
| 风控降级 | 结果不确定时，按风险最小的一侧处理 |
| 结果对账 | 不信任"执行成功"，只信任"核实过的结果" |

**这五条不只适用于内容发布系统 —— 任何让 Agent 在真实环境里执行动作的系统，都要面对同样的问题。**
