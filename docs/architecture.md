# 架构说明

## 一、整体数据流

```
① 项目初始化          create_project.py        建立项目目录骨架与问题集
        ↓
② 知识库下载          ima_download.py          按关键词递归拉取素材（含图片）
        ↓
③ 提示词生成          generate_prompt.py       按问题集批量生成生文提示词
        ↓
④ 文章生成            （子代理并行）            每个问题一个代理，产出文章
        ↓
⑤ 审查校对            check_articles.py        禁用词 / 标题字数 / 图片 / Q&A 格式
        ↓
⑥ 文档导入            feishu_import.py         导入飞书 / 腾讯文档，回填在线链接
                      tencent_import.py
        ↓
⑦ 多平台发布          article-publisher        9 个平台适配器 + 节流 / 重试 / 续跑
        ↓
⑧ 结果回填与对账       backfill / 汇总脚本      抓取发布状态 → 链接回填 → TSV 汇总
```

**关键设计**：每一步的产物都落盘（文章、图片、映射表、状态文件），因此任何一步失败都可以单独重跑，不必从头开始。

---

## 二、三层架构

### 1. 任务编排层

职责：管理一个「批次」从开始到结束的全过程。

- **批次定义**：一个批次 = 一个项目的一轮交付（例如 N 篇文章 × M 个平台）；
- **状态单元**：以「文章 × 平台」为最小状态粒度，每一步完成后立即持久化；
- **断点续跑**：启动时先读状态文件，跳过已完成单元，只补未完成的；
- **节流调度**：同一平台的发布动作串行化，并保证最小间隔（见 reliability.md）；
- **汇总输出**：所有单元的最终状态汇总为 TSV，供人工核对与交付。

### 2. 平台适配层

职责：把「发布一篇文章」这个动作，适配到 9 个规则各异的第三方平台。

统一接口（每个平台适配器都要实现）：

| 接口 | 输入 | 输出 | 说明 |
| --- | --- | --- | --- |
| `login` | 平台标识 | 登录态文件 | 首次人工登录，后续复用；启动前做轻量探活 |
| `prepare` | 文章（主/备标题、正文、图片） | 平台专属载荷 | 正文清洗、标题分配、图片处理 |
| `publish` | 平台专属载荷、模式（草稿/正式） | 结果（成功 / 失败 / 不确定） | 含节流等待与单篇重试 |
| `query_status` | 文章标识 | 草稿 / 已发布 / 不存在 | 用于幂等判断与结果对账 |

**为什么要抽象这一层**：9 个平台的差异集中在适配器内部，编排层只依赖接口。新增平台 = 实现接口 + 写一份 playbook，**主流程零改动**。

### 3. 质量校验层

职责：在任何一步产出后做可自动判定的检查，把问题挡在交付之前。

- 内容侧：禁用词、标题字数、Q&A 格式、图片完整性；
- 发布侧：正文是否完整粘贴、图片是否插入、标题是否错位；
- 结果侧：发布状态抓取、链接回填、抽样人工校验。

---

## 三、平台适配层为什么用 Playwright

发布目标是第三方网站，没有可用的开放 API，因此只能驱动真实浏览器：

- **复用登录态**：每个平台独立持久化浏览器上下文，避免互相污染，也避免反复登录触发风控；
- **真实交互**：正文通过剪贴板/本地中转文件写入富文本编辑器，处理图片上传与板块选择；
- **可观测**：失败时保存截图与 DOM 快照，便于事后定位是"页面变了"还是"网络抖了"。

## 四、目录约定

```
发布工作区/
└── <项目名>/
    ├── articles/                 # 待发布文章（含图片）
    ├── articles_meta.json        # 文章元数据（主/备标题、图片映射）
    ├── platforms.json            # 本次发布的平台清单与约束
    ├── logs/
    │   ├── <平台>_result.tsv     # 每平台发布结果
    │   └── dump_<平台>.json      # 发布后状态抓取结果
    ├── 发布汇总.tsv               # 最终对账表（人工核对入口）
    └── *.state.json              # 断点续跑状态文件
```

> 本仓库只保留脚本与模板，批次产物（文章、图片、日志、状态文件）均不进入版本库。
